# Vista Turbo RS232 0.2.6 RC16

RC16 corrects semantic-integrity problems in the VISTA command model and audit path discovered during final review of the command-model work.

## Command model corrections

- Normalize automatic unbypass through the documented `#77` action 31 flow using a configured Zone List number (`01`-`15`). Explicit zone numbers are rejected instead of being encoded into a fabricated unbypass sequence.
- Preserve one canonical command representation across Home Assistant semantic requests, compiled keypad execution, parser output, and administrator audit records.
- Restrict generic `system_command` execution to documented one-shot namespaces. Prompt-driven event-log, clock, output, access, `#77`, scheduling, and timer functions must use typed or explicit interactive transactions.
- Add documented `#77` action 65 access-group lock handling and correct the all-partitions `0` round trip.
- Validate action-specific `#77` specifiers before assigning high parser confidence.
- Reject semantic operands that the selected command cannot consume.

## Audit completion

- Treat `acknowledged_unverified` as a terminal audit result so successful keypad operations that cannot be fully proven from panel telemetry receive a completion timestamp instead of remaining open.

## Validation

The merge candidate passed 222 backend tests, repository security guardrails, JavaScript and shell syntax checks, and 49/49 Playwright frontend tests. The RC16 release commit is independently gated by the repository's exact-commit release workflow before publication.

## Compatibility

RC16 is a backend command-model correction over RC15. The physical virtual-keypad behavior introduced in RC14 is unchanged, including immediate keypress delivery with no synthetic SEND control. The keypad card remains version `0.3.26`.
