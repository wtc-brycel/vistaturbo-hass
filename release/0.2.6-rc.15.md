# Vista Turbo RS232 0.2.6 RC15

RC15 fixes the MQTT bootstrap regression that could leave Home Assistant showing VISTA offline while the bridge was actively connected to the panel and receiving valid state.

## MQTT bootstrap availability fix

- Raise the Home Assistant App's internal bounded Paho outbound queue from 256 to 4096 messages.
- Keep queue sizing internal after the configuration cleanup in #28; RC15 does not re-expose the engineering tuning option in the Home Assistant Options editor.
- Existing stored `mqtt_outbound_queue_max` values are removed by the #28 option migration before the supported internal runtime default is applied.
- Preserve the bounded-queue hardening: RC15 does not restore Paho's unlimited disconnected outbound queue.

## Field failure reproduced

The RC13 field log showed MQTT connecting successfully followed by 1,376 `MQTT_ERR_QUEUE_SIZE` (`rc=15`) rejections during startup discovery/state publication. Rejected topics included `vista128/panel/state_fresh` and Home Assistant discovery topics even though the VISTA TCP session established normally, startup synchronization completed, and a valid partition 1 keypad display was received.

## Compatibility

RC15 is based on the current `main` after #28. It preserves the streamlined Home Assistant Options surface and the RC14 keypad behavior; the keypad card remains `0.3.26`.

## Separate historical-log observation

The same field log also showed the explicitly enabled experimental startup historical event-log dump later timing out and causing panel reconnect churn. That is separate from the MQTT false-offline regression. Historical startup dump remains disabled by default pending further physical-panel hardening.
