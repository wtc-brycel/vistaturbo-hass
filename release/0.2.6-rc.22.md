# Vista Turbo RS232 0.2.6 RC22

RC22 hardens Home/Facility Automation suspension handling around VISTA `08XF` / `08XN` flow-control messages.

- Treat `08XF` as a generic automation-interface suspension rather than assuming it always means installer programming; Honeywell also emits it during telephone/central-station activity.
- Continue quiescing keypad polling and periodic automation traffic while Communication Off is active.
- Mark Home Assistant panel state stale/unavailable immediately on `08XF` while preserving last-known values for diagnostics/history.
- Use explicit `AD` / `BD` system events as programming-mode evidence when available.
- Report Automation Availability Source as `programming` only when programming has been explicitly observed; otherwise use `communication_off`.
- Keep the RC21 fix that treats `08XF` as a terminal response for an in-flight control transaction instead of manufacturing an ACK timeout and reconnect loop.
- On `08XN`, clear the quiesced/programming state and require a full state resynchronization before the snapshot becomes fresh again.
- Add regression coverage for generic Communication Off, explicit programming plus Communication Off, and Communication On recovery.

A separate research issue tracks whether local installer programming can be forcibly exited over the serial connection. RC22 does not send speculative recovery frames while the panel has disabled Home/Facility Automation.
