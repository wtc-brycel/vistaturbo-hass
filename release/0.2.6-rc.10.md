# Vista Turbo RS232 0.2.6 RC10

RC10 adds first-class Home Assistant alarm binary sensors and panel-wide alarm aggregation. Frontend card remains `0.3.22`.

## Alarm binary sensors

Per configured keypad partition, Home Assistant now discovers:

- Fire Alarm
- Burglary Alarm
- Auxiliary Alarm
- Alarm Active

The bridge also discovers panel-wide primary entities:

- Fire Alarm
- Burglary Alarm
- Auxiliary Alarm
- Alarm Active

The panel-wide entities OR alarm state across all eight VISTA partitions. Any partition reporting a fire, burglary, or auxiliary alarm immediately turns the corresponding panel-wide entity ON, even when that partition is not in the configured keypad polling list.

To avoid false OFF states after a reconnect, derived alarm entities use explicit validity availability. An active alarm is always authoritative ON. OFF is only published when the configured partition set is known false; otherwise the entity is unavailable until state is re-established.

Panel-wide entity attributes include the partitions currently driving each alarm class. The aggregate Alarm Active entity also exposes active alarm types and their active partition lists.

## Reconciliation

An authoritative arming status of Disarmed or Not Ready/Disarmed now clears stale burglary-specific event state as well as the general alarm token set. Fire and auxiliary alarm state continue to follow their own restore/latch semantics.

## Keypad display refresh

Virtual keypad control already schedules an asynchronous keypad display refresh after every accepted keypress. Live VISTA system events also schedule a display refresh. Refreshes are coalesced using `keypad_event_refresh_delay_ms` so rapid code entry is not blocked behind a KD request after every digit.

## Frontend

No frontend code changed in RC10. Continue using:

```text
/local/vista-keypad-card.js?v=0.3.22
```

Experimental panel control remains disabled by default.
