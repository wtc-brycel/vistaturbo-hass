# Vista Turbo RS232 0.2.6 RC11

RC11 is the coordinated security-hardening release for issues #16, #17, and #18. CI and release supply-chain changes from #19 are intentionally not included.

## Security state and transactions

- Panel-wide alarm state includes fire, burglary, auxiliary, silent, duress, supervisory, and other decoded alarm evidence.
- Positive alarm evidence is published immediately. A safe OFF state is published only after a complete arming, zone, zone-partition, and all-eight-keypad snapshot; otherwise the alarm entity is unavailable.
- TCP reconnects invalidate session-derived security state while retaining configuration and the SQLite event journal. READY, DISARMED, keypad, and alarm state is not republished as current before resynchronization.
- Synchronization, control, and keypad display responses use transaction ownership. Keypad responses are checked against the partition in the response, and control sequences of up to five keypad strokes are serialized as one logical MQTT command. The frontend keeps one interaction ID while it segments longer input into `complete:false` frames and uses an explicit SEND action for the final `complete:true` frame; inactivity never completes a command.
- Control and raw transmit queues are bounded. Raw transmit is privileged, disabled by default, limited to the `admin/raw_tx` topic, validated to 512 bytes, and cannot starve normal control traffic.

## MQTT and diagnostics

MQTT TLS can be enabled with broker certificate verification and optional CA and client certificate/key settings. TLS failures never fall back to plaintext. Plaintext remains available for trusted, isolated LAN deployments. Broker ACLs are required in either mode, and should grant normal control topics without granting `vista128/admin/raw_tx`.

Raw MQTT frames and raw payload logging are disabled by default. Opt-in frame diagnostics include validity, checksum, message type, length, and timing metadata; retained raw ASCII is removed. Control payloads are redacted from logs and result telemetry. The bounded local keypad audit intentionally stores completed logical command sequences, including PINs when they form part of the command, for the configured administrator.

Paho's disconnected QoS outbound queue is bounded to 256 messages by default, with a 20-message in-flight window. Publish overflow is observable and is not moved into an unbounded application retry queue.

The panel serial-server TCP protocol remains unauthenticated plaintext. Its checksum detects transmission errors but does not authenticate a sender. Put the serial server on an isolated security VLAN and firewall it so only the bridge can connect. Optional printer HTTP has the same trusted-network assumption; an HTTP response does not prove physical printing. Pending printer jobs and terminal spool history are bounded by `transport_print_queue_max`.

SQLite event history defaults to 90 days and 10,000 rows. It contains sensitive panel/security information.

## Frontend and migration

Card `0.3.24` renders an explicit offline state and disables controls for unavailable source entities, rejects unsafe CSS color expressions, and uses bounded searchable entity inputs in the visual editors. Keypad input is buffered until the user presses SEND, then sent as non-retained QoS 1 JSON. Longer input is segmented into five-key `complete:false` frames followed by one final `complete:true` frame using the same interaction ID. The bridge still accepts one-key JSON and legacy one-byte key commands for compatibility; the exact completed logical sequence is stored only in the bounded local administrator audit, not in HA entities or control-result telemetry.

Replace the card resource with `vista-keypad-card.js?v=0.3.24`. Existing bridge settings remain compatible; new options default to safe values:

```yaml
mqtt_tls_enabled: false
raw_mqtt_enabled: false
raw_logging: false
keypad_audit_enabled: true
event_history_max_age_days: 90
event_history_max_rows: 10000
tx_queue_max: 128
raw_tx_queue_max: 16
mqtt_outbound_queue_max: 256
mqtt_inflight_messages_max: 20
```

If raw transmit is explicitly enabled, update broker ACLs and operational tooling to use `vista128/admin/raw_tx`; the old confirmation phrase was never authentication and is no longer accepted.
