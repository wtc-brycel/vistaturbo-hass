# Vista Turbo RS232 0.2.6 RC26

RC26 adds native Lantronix RFC2217 / TruPort serial control after real-hardware RC25 testing showed that generic Telnet negotiation alone was insufficient for a Lantronix configuration that works through Com Port Redirector (CPR).

- Preserve transparent raw TCP behavior for serial servers that do not use Telnet control traffic.
- When a Telnet-mode Lantronix is detected, initiate the Lantronix-documented RFC2217 handshake using COM-PORT-OPTION (`0x2C`).
- Use the CPR/CoBos-compatible Telnet preamble: `WONT ECHO`, `DONT ECHO`, `WILL SUPPRESS-GO-AHEAD`, and `DO COM-PORT-OPTION`.
- Support the standard RFC2217 server-`DO COM-PORT-OPTION` negotiation direction as well.
- Configure the remote serial port for the known-good VISTA connection: 9600 baud, 8 data bits, no parity, one stop bit, and no flow control.
- Request RFC2217 line-state and modem-state masks in the Lantronix-documented order.
- Consume RFC2217 acknowledgements, modem/line-state notifications, and other subnegotiation traffic before it reaches the VISTA frame parser.
- Correctly escape literal `0xFF` bytes in both serial payloads and RFC2217 subnegotiations.
- Preserve fragmented-TCP handling across Telnet commands and RFC2217 subnegotiations.
- Add transport- and bridge-level regression coverage for the Lantronix/CoBos handshake, serial configuration, acknowledgements, fragmentation, and raw-TCP compatibility.

RC26 retains the non-configurable installer-programming safety interlock introduced in RC24. No VISTA framing, synchronization, panel-control, or state semantics are otherwise changed.
