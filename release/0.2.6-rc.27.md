# Vista Turbo RS232 0.2.6 RC27

RC27 adds Telnet BINARY negotiation and explicit transport diagnostics for legacy Lantronix serial servers after RC26 hardware testing showed that the TCP/Telnet session still was not passing VISTA responses.

- Request Telnet BINARY in both directions with `WILL BINARY` and `DO BINARY` so VISTA serial bytes, including CR/LF framing, are not subject to Telnet NVT character translation.
- Track panel-to-bridge and bridge-to-panel BINARY acceptance/refusal independently.
- Keep RFC2217 COM-PORT-OPTION probing optional. If the serial server refuses RFC2217, Vista Turbo continues with the device server's configured serial parameters instead of treating RFC2217 as required.
- Add safe INFO-level Telnet negotiation diagnostics showing symbolic `WILL`, `WONT`, `DO`, and `DONT` option exchanges.
- Log whether BINARY mode is accepted or refused in each direction.
- Log whether RFC2217 COM-PORT-OPTION is accepted or refused and report RFC2217 subnegotiation command numbers without logging their payloads.
- Preserve raw-TCP compatibility, stateful fragmented-IAC handling, RFC2217 support when accepted, and literal `0xFF` escaping.
- Add regression coverage for bidirectional BINARY negotiation, refusal handling, optional RFC2217 fallback, fragmentation, and bridge-level control isolation.

Transport diagnostics do not log VISTA serial payloads, keypad codes, alarm codes, or credentials. RC27 retains the non-configurable installer-programming safety interlock introduced in RC24.
