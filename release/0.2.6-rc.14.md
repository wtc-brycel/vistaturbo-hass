# Vista Turbo RS232 0.2.6 RC14

RC14 is an urgent frontend regression correction for the virtual VISTA keypad.

## Keypad behavior

- Remove the synthetic **SEND** button and the "Press SEND to finish the command" workflow entirely.
- Restore physical-keypad semantics: each `0-9`, `*`, or `#` press is published immediately when pressed.
- Preserve press ordering within the card and retain bridge-side serialization for panel traffic.
- Publish each key as a non-retained QoS 1 one-key JSON request with `complete: true`, partition, Home Assistant actor attribution, and a unique control transaction ID.
- Use a separate short-lived audit interaction ID to group rapid human entry into one bounded administrator-local audit row without delaying any keypad press or using audit identity for panel control ownership.
- Keep entered digits out of browser DOM-event details and normal result telemetry.
- Preserve the existing read-only/card control gates and unavailable-panel fail-safe behavior.

## Regression coverage

- Assert there is no SEND/finish-command control in the rendered keypad.
- Assert rapid entry publishes every physical key in exact order.
- Assert slow entry is delivered immediately and does not depend on inactivity or a completion boundary.
- Assert `*` and `#` are delivered literally and immediately.
- Assert control and audit interaction IDs remain separate so PIN digits are not stored as independent audit rows.
- Preserve actor-attribution, read-only, bridge-gate, and redacted-DOM-event tests.

The bridge/App version is `0.2.6-rc.14`. The keypad card is `0.3.26`.
